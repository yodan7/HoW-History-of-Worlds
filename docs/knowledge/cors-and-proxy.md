# CORSエラー (403 Forbidden) とその回避策について

## 問題の背景

React (Vite) 環境から `REST Countries API (v5)` に `fetch` でリクエストを送信したところ、ターミナルからの `curl` コマンドでは成功するにもかかわらず、ブラウザ上では **`403 Forbidden`** エラーが発生しました。

## 原因：CORS（Cross-Origin Resource Sharing）の制限

ブラウザには、悪意のあるサイトが勝手に別のサーバーからデータを抜き取るのを防ぐためのセキュリティ機能（**CORS**）が備わっています。
APIサーバー（今回ならREST Countries）は、リクエストが「どのドメイン（Origin）から来たのか」をチェックし、自分が許可していないWebサイト名（今回は `localhost`）からの通信だと「横取りしようとしている！」と判定して強制的にブロックします。これが今回の403の正体です。

---

## 解決策・学んだこと

この状況を突破するための、エンジニアとしての2つのアプローチについて整理します。

### 解決策A：APIの管理画面で「許可」をもらう（正攻法）

一番真っ当な方法は、APIの提供元（ダッシュボード等）に「このURLからの通信は怪しくないから通してね」と登録することです。

- **やり方**:
  - APIダッシュボードの「Allowed Origins（許可する送信元）」などの欄に、自分の開発環境（`localhost` や `127.0.0.1`）や、公開時のURL（`https://myapp.com`）を事前に追加しておく。
- **メリット**:
  - 本番環境（公開時）に向けた正しいセキュリティ設定ができる。
  - フロントエンドのコード（React側）を一切複雑にする必要がない。
- **デメリット**:
  - APIによっては `localhost`（ローカル環境）の登録をそもそも許可していなかったり、入力形式に独自のルール（カンマ区切り、httpは不要など）があったりしてハマりやすい。

### 解決策B：Viteの「Proxy（プロキシ）」機能を使う（裏ワザ・開発用）

ダッシュボードの設定がうまくいかない場合や、そもそも開発環境からのアクセスをAPI側が許可してくれない場合に使う、Vite（開発サーバー）の強力な機能です。

ブラウザのCORSチェックは「ブラウザ → 別のサーバー」の通信でしか発動しません。
「サーバー → サーバー」の通信ではCORSチェックは存在しません。

- **やり方**:
  - `vite.config.ts` を修正し、Reactからの通信を一旦Viteのローカルサーバーで受け取り、Viteサーバーが「肩代わり」してAPIサーバーへ取りに行くように設定（プロキシ/身代わり設定）を記述する。
  ```typescript
  // Reactからの fetch('/api/countries') を
  // Viteが裏側で https://api.restcountries.com/... にすり替えて通信してくれる
  ```
- **メリット**:
  - API側のダッシュボード設定に頼らず、開発者のPC側だけの工夫で100%確実にエラーをなきものにできる。
- **デメリット**:
  - これはあくまで「ローカル開発用の仮設定」であるため、本番環境で公開する時はサーバーに別のプロキシ設定を組むか、結局は（解決策A）のように本番URLをダッシュボードに登録する必要がある。

---

## 例え話

**【解決策A：ダッシュボード設定】**
高級マンションのエントランス管理人に、「後でウーバーイーツ（localhost）が来るから通してあげてね」と事前に連絡を入れておく方法。

**【解決策B：Proxy設定】**
マンションの管理人が絶対に外部の人間を入れてくれないので、住人である自分（Vite）がこっそりエントランスまで商品を受け取りに行き、自分の部屋の中（React）まで自分で持っていく方法。管理人にはバレない。
